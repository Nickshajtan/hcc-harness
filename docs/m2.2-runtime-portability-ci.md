# M2.2 permanent runtime portability gate

Status: validation in progress. B1 is not complete until the mandatory Ubuntu,
macOS and Windows runtime jobs pass. B2 is not authorized.

`runtime-feasibility.yml` runs on every push, pull request, merge-group event and
manual dispatch, with no path filters. The three platforms run the **same nine
contract tests** in `tests/feasibility/runtime-contract.test.ts` with actual Node
24.19.0 and 22.12.0 subprocesses. Windows additionally builds and tests the native
bootstrap and the existing 21 executable/isolation assertions (including Node 20).
The standalone terminal runner verifies all three TTY handles, keyboard input and
exit 9 with native Node 22 on each platform.

The contract covers independently selected Arch and native engines, incompatible
runtime rejection, real npm-generated PATH and adjacent-Node shims, exact args,
environment/cwd/stdio, native exit 23, concurrent runtimes, console termination and
cleanup, missing/replaced historical Node, and relocated historical checkout.
Legacy recovery uses genuinely initialized owned resources and a current Arch
installation for status/deinit; it never executes old launchers. Repeated deinit
and explicit init preserve user-edited middleware bytes.

The normal regression suite retains its existing M1/M2/M2.1 coverage. Provisioned
runtime tests are opt-in in normal local runs; **the mandatory workflow enables
them and rejects missing prerequisites, failed assertions, and any skipped tests**.
No unsupported platform is silently accepted. The aggregate check named
`M2.2 runtime portability required` succeeds only when the entire matrix succeeds.

## Real managers versus simulation

One separate assertion changes PATH between isolated copied Node 22/24 binaries.
This is explicitly **PATH simulation**, not an nvm/fnm test.

Another assertion invokes the real pinned mise 2026.10.11 executable: `mise link`
registers pre-provisioned local runtimes under temporary MISE_DATA_DIR, then
`mise exec node@22.12.0`, `node@24.19.0`, and `node@22.12.0` switches native runtimes
while ARCH_NODE remains independent. It runs offline, with isolated HOME,
config/cache/data and project directories. No runner-global installation, prefix,
profile, or configuration is changed. nvm/fnm: **NOT TESTED**.

## Evidence and limits

Each matrix artifact `m22-runtime-<os>` contains Vitest JSON, terminal JSON and
`m22-runtime-summary.json`. GitHub step summaries show PASS / FAIL / NOT TESTED.
Missing evidence causes a nonzero summary step; assertion failures are never
converted into warnings. Required aggregate status must be configured on main
after the implementation passes CI.

Bootstraps are **opt-in feasibility prototypes**, not installed production entries.
The POSIX shell prototype implements the approved explicit ARCH_NODE / first PATH
Node policy, preserves the environment and execs the fixed adjacent dist/cli.js.
Unlike the Windows native prototype, its version probe is not bounded; adversarial
or stalled runtime executables remain an integration risk. Only trusted explicitly
selected runtimes are used in this contract. Prototype engine-range metadata must
be kept in sync before production integration.

Temporary app layouts link dependencies to the current repository. They do not
prove self-contained stable installation or source-deletion independence. Historical
launcher breakage is recovered explicitly through current status/deinit/init;
automatic rebind is not implemented. Windows ARM64 and B2 stable installation:
**NOT TESTED**. Core, EDA, middleware APIs and production setup/manifest formats
are unchanged by this CI addition.
